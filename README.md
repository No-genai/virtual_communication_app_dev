# こもれび / Komorebi Space 0.12.3

イベント・授業向けに拡張した、独自の2D交流スペースです。MetaLifeのコード・画像・デザインの転載はしていません。**MetaLifeの全機能と同等の完成品ではありません。** 機能ごとの状況は [機能一覧](docs/FEATURES.md) を参照してください。

## 村のオブジェクトを通り抜け（0.12.3）

4つの村と単独の都会・農業・天使・ボスの村では、風車・畑・木・建物などの上をそのまま歩けます。追加配置したオブジェクトも村では装飾扱いです。クリック・タップ・矢印キーの移動に共通で適用され、画面外への移動制限は残ります。保存済みの村にも適用され、データ削除は不要です。教室・庭・ラウンジの家具の衝突判定は従来通りです。

## 農村の通路修正（0.12.2）

風車と畑の間の見えている通路が、障害物周辺の余白で塞がれていた問題を修正しました。足元の衝突半径を6pxとし、細い通路も経路探索できるようにしました。クリック移動の曲がり角では目的座標を越えないよう移動距離を制限します。畑・風車そのものには入れません。マップデータの削除は不要です。

## 中央広場の移動修正（0.12.1）

中央の木の当たり判定を根元に合わせ、周囲の広場を歩けるようにしました。クリック・タップ移動は障害物を迂回し、障害物そのものを選んだ場合は近くの通行可能な地点へ向かいます。保存済みの標準4村マップも起動時に更新します。独自に編集したマップは変更しません。

## GitHubの使い方（0.12）

都会の村の本から6ステップの学習コースを開けます。リポジトリ閲覧 → クローン → 編集・差分 → コミット・プッシュ → PR → マージ。各章に説明と練習手順、2問のクイズを用意しました。まとめテストは各章1問ずつの6問。誤答から該当章を読み直せます。読了チェックはこのブラウザに保存します。

`git_practice`を題材に自分のForkで練習する構成です。コマンドは利用者がPCで実行します。アプリがGitHubへ書き込むことはありません。問題・説明は独自作成です。

## 焚き火・交流の目印・学びの広場（0.11）

- **話題の焚き火**：中央の焚き火をタップするか、アクション・遊びから開きます。輪（半径90）に集まった参加者同士は、所属する村をまたいで通常チャットが届きます。輪の外には通常の発言は届きません。全体チャット・DMの宛先は従来通りです。「次のお題」は輪の中の人が5秒以上の間隔で切り替え、同じスペースに同期します。お題は8種類の固定文です。音声は通話に参加した人だけが対象で、実ネットワークの受信未検証事項は継続しています。
- **交流の目印**：話しかけてOK・質問したい・見学中・集中中・目印なし。アバターと参加者一覧に表示し、同じブラウザに保存します。マイクやカメラをONにする機能ではありません。
- **GitHub・Linuxの学びの広場**：都会の村の本をタップして開きます。0.11では各分野7問ずつの一般問題を用意しました。0.12のGitHub単独コースは上記の章別問題に更新し、Linux・旧まとめコースは従来の問題から1回6問を出題します。選択式の採点・解説・公式リファレンス・間違えた問題の振り返りに対応しています。学習結果は本人だけに返し、永続保存や主催者の成績一覧は未実装です。1回の有効時間は20分で、再入室・サーバー再起動時にはリセットされます。自主学習用で、本人確認を伴う認定試験ではありません。

**スパルタ塾の全教材への対応は未完了です。** 指定されたNotionページは環境のネットワーク制限（403）で取得できておらず、一般基礎問題を教材由来の問題として扱っていません。利用者は教材の「一部」ではなく「全体」を希望しています。サブページを含むMarkdown ZIP等の提供後に、全章を確認し、章別問題・理解度テスト・復習へ反映する作業が残っています。詳細は [学習機能の状況](docs/LEARNING.md) を参照してください。

## 明るさ・マップの拡大（0.10）

初期の景色は晴れ・昼・春です。夜にアクセスしても自動で暗くなりません。自動の時間・季節や夜の景色は引き続き選択でき、夜の暗幕も薄くしています。主催者が保存した景色は保持するため、既存スペースに夜が保存されている場合は「アクション・遊び → 天気・時間・季節」から昼を選べます。

重複するタイトル・常設の操作説明を省き、マイク・カメラ・画面共有・通話映像は「通話設定」にまとめました。通話参加ボタンは常設です。1280×720の基本画面でマップは約830×564pxとなり、0.9の約600×408pxに比べて表示面積が約1.9倍になりました。ページのスクロールは不要です。

## ペット・相乗り・四季・記念撮影・着せ替え（0.9）

マップ下の「アクション・遊び」にまとめています。常設の操作パネルは増やしていません。

- **ペット**：ねこ・ひよこ・小さな竜から選択。歩くと後ろをついてきて、「ペットをなでる」でハートを表示します。装飾なので移動や会話を妨げません。
- **着せ替え**：帽子（なし・ベレー帽・王冠・花かんむり）、服（コート・しましま・マント）、小物（マフラー・リボン）を組み合わせ、見本を見て適用できます。もとの服にも戻せます。アバターの種類と服の色はプロフィールから変更します。ペット・服装の組み合わせは同じブラウザに保存し、再入室時に復元します。
- **相乗り馬車**：「馬車を出す」→近くの人を招待→相手が30秒以内に承諾。運転手を含め3人まで。運転手が移動し、同乗者は「降りる」または0キーで自由に降りられます。運転手の降車・退出・切断やブロック時も同乗を解除します。自動巡回ではありません。同乗者の移動先は運転手に従うため、村ごとの会話の対象も変わります。
- **景色**：晴れ・雨・雪、昼・夕暮れ・夜、春夏秋冬。時間帯と季節の「自動」は日本時間の暦に合わせます（北半球の季節）。天気は演出で、予報連動ではありません。「自分の画面で楽しむ」は一時的な個人設定。「全員に反映」は主催者専用で保存されます。個人設定中は「共有の景色に戻す」で共有設定に戻れます。共用ラウンジに主催者はいないため個人設定をご利用ください。
- **記念撮影**：その瞬間のマップ・アバター・ペット・参加者名・景色を日付入りPNGとして保存します。チャットやカメラ映像は含みません。スマホは見本画像の長押し保存も利用できます。実機の保存操作は未検証です。

乗車状態・招待・なでた反応は一時的な状態です。乗車中は運転手のペットを描画します。装飾の歩行追従や天気の粒子は「動きを減らす」設定で静止表示になります。

## スクロール不要の基本画面・数字ショートカット（0.8）

画面の高さに合わせてマップを表示し、マップ・村の移動・アクション・通話・チャットをPCの1画面にまとめました。スマホでは「チャット・参加者」と「マップに戻る」で切り替えます。履歴・参加者一覧・設定ダイアログなどの長い内容は各パネル内でスクロールします。

マップを選択して、数字キーで操作できます。1：ハート、2：手振り、3：拍手、4：ダンス、5：挙手／手を下ろす、6：走る／歩く、7：馬車に乗る／降りる、0：歩きに戻る・ポーズ終了。文字入力中やダイアログ表示中は作動しません。キーの長押しによる連続切替も抑止しています。「アクション」メニューからクリックやタップでも選べます。

## 動くアクション（0.7）

マップ下の「アクション」メニューでハートポーズ・手振り・拍手・ダンスを選ぶと、アバターの腕や体が5秒間動き、同じスペースの参加者にも表示されます。「挙手」は手を上げたままになり、ポーズより優先されます。解除は「手を下ろす」です。従来のリアクションボタンも対応するポーズと連動します。

「走る」で移動が速くなり、「馬車に乗る」で馬車を操作できます。矢印・WASD・クリックで移動し、同じボタンをもう一度押すか「歩きに戻る・ポーズ終了」で解除します。馬車は手動操作です。0.9では招待による最大3人の相乗りに対応しました。自動巡回・停留所・村限定アクションは未実装です。移動速度と当たり判定はサーバーが管理します。動きを減らすOS設定ではポーズを静止表示し、揺れ・足踏み・土ぼこりを抑えます。

## ひと続きの風景に4つの村（0.6）

中央の木、石畳、外周の森がつながる一枚のドット絵マップです。元の4軒の家の位置に **左上：都会 / 右上：農業 / 左下：天使 / 右下：ボス** の小さな村を配置しています。村名ボタン、または徒歩で移動でき、村名の色と人数で現在地を確認できます。マップはコンテンツ幅いっぱいに表示されます。

- 通常チャット「今いる村の部屋」と通常通話は、同じ村の参加者を対象にします。境界で隣り合っていても別の村には通常の発言を配信しません。
- 「4つの村全体」を明示的に選ぶチャット、お知らせ、主催者の「全体へ配信」は全村向けです。DMは村をまたいで宛先を選べます。
- 掲示板・ホワイトボード・投票は全村共通です。村ごとの個別パスワードや主催者権限はなく、スペース単位で管理します。
- 定員は4村を合わせて最大30人です。通常通話の近い6人までという接続数制限と、音声・映像の到達未検証事項は継続しています。村内の通常チャットには距離制限をかけません。

新しいスペースのテーマは「4つの村がつながる広場」を選択してください。既存スペースも「主催者メニュー → マップ編集 → マップテンプレート」で切り替えられます。過去の保存データを引き継いだ場合は、既存のテーマを勝手に変更しません。共用ラウンジを新規に作った環境では最初から4つの村の共通マップです。

## 特徴が分かる4つの村（単独表示も可能）

- **都会の広場**：ネオン、横断歩道、街のアート。
- **農業の村**：麦や野菜の畑、風車、収穫かご。
- **天使の村**：雲の海、白い翼の天使、金色の光。
- **ボスの村**：溶岩、結晶、大きな守り竜。

「新しいスペースを作る → 村のテーマ」で見本を見て選択できます。既存のスペースでは「主催者メニュー → マップ編集 → マップテンプレート → テンプレートを適用」で変更します。変更は全参加者に同期され、再起動後も保存されます。作成画面の初期選択は4つの村の共通マップです。各村を単独表示することもできます。共用ラウンジには主催者がいないため、自分のスペースで切り替えてください。

入れそうに見える家やドアは描画しない構成に変更しました。天使と守り竜は装飾キャラクターで、会話イベント・戦闘はありません。装飾を追加/削除できますが、テーマ変更時は配置がテンプレートに置き換わります。従来のこもれび広場・ガーデン・青空教室も引き続き利用できます。

## ドット絵のアバター（0.3から継続）

背景もキャラクターもオリジナルのドット絵です。入室画面では8種類から1体が自動で選ばれます。「おまかせで選び直す」で別の候補に変更したり、一覧から直接選んだりできます。服の色も5色から選べます。入室後は「プロフィール」で着替えられ、他の参加者にも同期されます。

旅びと／星よみ／森の番人／小さな騎士／吟遊詩人／パン職人／見習い学者／花の世話人の8種類。キャラクターと背景は独自のプログラム描画で、既存ゲームの画像・音楽・ロゴを使っていません。名前と服の色は同じブラウザに保持され、アバターの種類は新しいページを開くとおまかせで選ばれます。通信再接続では選んだ種類を維持します。

歩行アニメーションと位置の補間を追加し、OSの「動きを減らす」設定ではアニメーションを抑えます。建物への入室機能はありません。家具の当たり判定・会話範囲・部屋機能は維持しています。

## Macで起動

Node.js 24 LTSを推奨（最低22.12）。ZIPを展開し、ターミナルに `cd ` と入力して展開フォルダをドラッグし、Enterを押します。そのフォルダで：

```sh
npm ci
npm run dev
```

ブラウザで `http://localhost:3000` を開きます。別タブでも参加して操作を確認できます。起動中はターミナルを開いたままにします。終了はControl+C。`index.html`の直接表示では動きません。

手順をまとめて実行する場合は `bash start-local.sh` も利用できます。初回の依存ダウンロードにはインターネット接続が必要です。

## 授業・イベントを始める

1. 入室画面の「新しいスペースを作る」で、名前と管理パスワード（10文字以上）を設定します。必要なら参加者用パスワードも設定します。
2. 自分の名前で入室します。作成したタブは主催者として参加します。別タブ・再起動後は「主催者メニュー」で管理パスワードを入力します。
3. 「招待リンク」でURLをコピーします。**localhostのリンクは別のPCからは利用できません。** インターネット越しの招待にはHTTPS公開が必要です。
4. 「主催者メニュー → 授業・イベント」でお知らせや理解度チェックの投票を送れます。参加者は挙手やリアクションで応答できます。
5. 掲示板に資料のHTTPSリンクを投稿したり、ホワイトボードで共同描画したりできます。
6. 「通話に参加」は受信のみ。マイク・カメラ・画面共有は個別のボタンで許可します。主催者は「全体へ配信」で距離に関係なく通話参加者へ配信する設定にできます。集中エリア・ブロック・離席は配信対象外です。

共用ラウンジには主催者がいません。管理機能を使う場合は自分のスペースを作ってください。管理パスワードのメール復旧機能はありません。

## 通話の検証状況と10〜30人の運用

カメラ・マイク取得、画面共有の開始/停止、WebRTCシグナリングを実装しています。クラウドのChromiumで、偽のテスト用デバイスと画面取得、offer/answerの交換まで確認しました。しかし管理ポリシー `WebRtcIPHandling=disable_non_proxied_udp` 等の通信制約下ではICE接続が完了せず、**遠隔への音声・映像受信は未検証**です。実メディア受信を要求する2つのE2Eテストは失敗状態を保持しています。ローカルTURN/TCPでも解決しませんでした。Mac実機・別回線・Safariの検証は未実施です。

現在はP2P方式で、通常の近接通話は相互に選ばれた近い6人まで。主催者の全体配信はこの人数制限の対象外ですが、参加者ごとに通信帯域が増えるため、30人配信の安定性を保証しません。**30人の入室・全体チャット確認は、30人の映像負荷試験ではありません。** 10〜30人の本番授業は、実機での確認とTURNの導入、映像利用数に応じたSFU（LiveKit等）の追加を行ってから運用してください。SFU統合は未実装です。

## 保存するもの

`data/rooms.json` に、スペース名・設定・パスワードのハッシュ・家具配置・掲示板を保存します。起動し直しても残ります。`data/` はGitや配布ZIPには含めません。バックアップはサーバー停止中にこのディレクトリを保管してください。単一Nodeプロセス用で、複数プロセスから同じファイルを更新する運用は未対応です。

チャット・投票・挙手・位置・ホワイトボード・ブロックはサーバー再起動で消えます。ホワイトボードはPNGで保存可能。CSV出力は「現在の参加者一覧」で、出欠履歴の記録ではありません。管理者セッションは8時間・サーバー再起動で失効します。再接続時の通話はOFFに戻り、ブロックも再設定が必要です。

## 本番モードと設定

```sh
npm run build
npm start
```

| 環境変数 | 意味 |
|---|---|
| `PORT` | 待受ポート。既定3000 |
| `HOST` | 待受アドレス。既定0.0.0.0。ローカル限定なら127.0.0.1 |
| `PUBLIC_ORIGIN` | 公開時の正確なorigin。例：`https://space.example.com` |
| `DATA_DIR` | 保存先。既定`data` |
| `ICE_SERVERS` | RTCIceServer形式のJSON配列。既定空。運用者がSTUN/TURNを設定 |

環境変数はシェルまたはホスティング環境で設定します。`.env` の自動読み込みはしません。TURNの認証情報は参加者ブラウザに渡される性質のため、制限付き短期資格情報を利用し、長期の共有秘密を配布しないでください。このバージョンはTURNの資格情報を自動発行しません。

HTTPSリバースプロキシではWebSocket転送も有効にしてください。開発モードを公開しないでください。ファイルアップロード、録画、SSO、アカウント管理、課金、公開サーバーの自動構築は未実装です。

## テスト

```sh
npm run build
npm test
CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e:core
CHROMIUM_PATH=/usr/bin/chromium npm run test:media
npm audit
```

Mac等でシステムChromiumを指定しない場合は `npx playwright install chromium` 後、`CHROMIUM_PATH`なしで実行します。`npm run test:e2e` はメディアを含む全ブラウザテストです。E2Eはポート3000にテスト用サーバーを起動するため、開発サーバーを停止してから実行してください。メディアE2Eはテスト用カメラ・マイク・画面を利用します。
