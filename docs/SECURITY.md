# セキュリティと運用範囲

## 実装済み

- 入室パスワードと管理パスワードはランダムsalt付きscryptでハッシュ化。平文の保存・参加者への配布なし。
- 管理者トークンはランダム256bit、8時間で期限切れ、ブラウザsessionStorage。部屋ごとに検証し、ワールド状態に混ぜない。
- 非公開ルームは公開一覧に出さない。チャット・DM・通話シグナリングの対象ルームと権限をサーバー側で判定。
- サーバー側の移動速度、範囲、家具判定。通常通話は近接/会議ゾーン・ブロック・離席/集中状態に応じて接続する。
- 名前20文字、本文300文字、掲示板500文字/50件、描画500ストローク/各100点、家具30個。メッセージ間隔やイベント頻度、接続・認証試行・ルーム作成に上限。
- 管理者のみ設定、入室停止、投稿削除、参加者退出、全体配信、投票開始/締切、地図編集を操作可能。
- DOM textContentで文字表示。共有リンクはHTTPSのみで、新規タブにnoopener/noreferrer。保存先へのHTTP経路は提供しない。
- Origin検査、本番CSP、nosniff、Referrer-Policy、カメラ等のsame-origin Permissions-Policy、静的ファイルのパストラバーサル拒否。
- JSONの一時ファイル→renameで保存。dataディレクトリは700、データファイル600。ファイル破損時は黙って空データに置き換えず起動エラーにする。

## 限界

ゲスト制なので、名前の本人確認・永続BAN・厳密な出欠や投票者数は保証できません。退出させても、招待URLと入室パスワードを知る人は再入室できます。必要なら入室停止またはパスワード変更を併用してください。登録アカウント・メール復旧・多要素認証・監査ログ・通報対応は未実装です。

Originは認証の代わりではありません。Proxy配下では送信元IPを推測するために無条件でX-Forwarded-Forを信頼しません。そのため接続/認証レート制限はProxy単位に集計される場合があります。複数サーバー用共有レート制限は未実装です。

位置とプロフィールは同じ部屋の参加者に見えます。近くのチャットやDMは配信先を制御していますが、サーバー運用者にも見えないE2E暗号化ではありません。ブラウザ間のメディアはWebRTCですが、ユーザーの録画や画面キャプチャを防げません。距離やミーティングエリアを機密情報の境界として扱わないでください。音声・映像の受信検証はこのクラウドでは完了していません。

ブロックは接続単位で、再接続後は再設定が必要です。主催者パスワードは単一の共有権限です。管理者の増減・個人単位の権限剥奪は未対応です。

保存された掲示板はバックアップに残り得ます。チャット、投票、描画はサーバー再起動で消えます。単一Nodeプロセス用で、書込失敗・ディスク容量・バックアップは運用監視が必要です。

## 公開と通話

開発サーバーは公開しないでください。本番はHTTPS、正確なPUBLIC_ORIGIN、WebSocket転送、秘密情報の適切な管理が必要です。TURNの長期共有秘密をICE_SERVERSとして参加者へ渡さず、短期かつ制限された資格情報を使ってください。資格情報発行サービスは未実装です。SFU・複数サーバー・30人同時映像の耐負荷性は未検証です。

npm auditの結果は既知の依存脆弱性に限り、アプリ全体の安全性の証明ではありません。ペネトレーションテストや第三者監査は行っていません。

## 4分割の村

4つの村は同一スペース内の会話グループです。座標から村をサーバーが判定し、通常チャットと通常通話のシグナリング対象を村ごとに分離します。移動ボタンの行き先も固定4種類に限定します。全村向けの発言・主催者配信・DMは明示的に村をまたぐことができます。アバター、掲示板、描画、投票、認証・管理権限はスペース共通なので、村ごとの独立した機密領域とは扱わないでください。
