# 技術選定と調査（2026-11-01）

## 調査の範囲

指定された [MetaLife スペース](https://app.metalife.co.jp/spaces/EF8oYs3aX9EA2ob9cFtRc) と [公式サイト](https://metalife.co.jp/) はネットワークプロキシが403を返したため、実画面・操作感・紹介動画は確認できていません。MetaLife固有の機能や内部実装は断定していません。今回の仕様は依頼文にある「2D空間を歩いて自然に交流」から設計しました。画像・コード・画面配置は転載していません。類似サービスとの実地比較は今後の調査項目です。

## 比較

| 技術 | 適性・負担 | ライセンスと保守の観測 | 判断 |
|---|---|---|---|
| 標準Canvas 2D | 小規模の俯瞰マップ。衝突・入力を自前で実装する必要あり | ブラウザ標準。追加パッケージなし | 今回採用。単一マップなら依存を減らせる |
| PixiJS 8.22.0 | GPU描画、多数のスプライト、複雑な演出に適する | npm記載MIT、更新2026-10-30 | マップ・アニメーション拡大時の候補 |
| Phaser 4.2.1 | ゲーム用シーン・入力・物理系を統合 | npm記載MIT、更新2026-07-09 | ゲーム要素が増える場合の候補。今回は規模に対して大きい |
| ネイティブWebSocket | 軽量。再接続・イベント設計を自作 | ブラウザ標準 | 小規模でも接続管理の作業が増える |
| Socket.IO 4.8.4 | イベント通信、自動再接続、切断検出、HTTP pollingへのフォールバック | MIT、更新2026-09-25 | 採用。WebSocketと直接の互換性はない |
| LiveKit client 2.23.0 | 音声・映像・データ。Cloudまたはセルフホストサーバーが必要 | Apache-2.0、更新2026-10-19 | 音声・映像フェーズで検討。認証、TURN/SFU、運用費の設計が必要 |

Node.js + Vite + JavaScript ES modules + Canvas + Socket.IO。状態の正本はNodeサーバーに置き、ブラウザからは方向入力だけを受け付けます。位置の検証・壁判定・会話範囲判定をサーバーで行います。小さなUIのためReactなどのUIフレームワークは導入していません。

## 確認した一次資料

- [Socket.IO README](https://github.com/socketio/socket.io/blob/main/packages/socket.io/Readme.md)：raw版を取得し、再接続・切断検出・フォールバックを確認。
- [LiveKit client README](https://github.com/livekit/client-sdk-js/blob/main/README.md)：raw版を取得し、Cloud/セルフホスト構成を確認。
- npm registry の socket.io / vite / pixi.js / phaser / livekit-client のバージョン、ライセンス、更新日時。更新日はパッケージメタデータの観測で、保守の継続保証ではありません。

MITとApache-2.0は商用利用を許可するライセンスです。ただし著作権・ライセンス通知の保持が必要で、Apache-2.0にはNOTICE等の条件があります。採用依存はロックファイルで固定。配布時には依存と同梱されるライセンス表示を保持してください。未採用候補の監査は未実施です。

## 0.2 更新（2026-11-04）

イベント・授業、10〜30人を想定した操作を追加しました。描画・通信の基本構成は維持しています。音声・映像はブラウザ標準のRTCPeerConnection、getUserMedia、getDisplayMediaを使用し、Socket.IOは接続情報の交換だけに使用します。固定3トランシーバー（音声・カメラ・共有画面）とID順のoffer生成で、不要な同時offerを避ける設計です。ブラウザ側実装は独自で、外部サンプルのコードをコピーしていません。

[WebRTC公式サンプル](https://github.com/webrtc/samples/blob/gh-pages/src/content/peerconnection/perfect-negotiation/js/peer.js) を読んで接続交渉の流れを確認しました。MetaLifeの公式サイトと指定スペースは再確認でも403となり、公式機能の完全な照合はできていません。

この環境のChromiumはWebRTCの直接UDPを制限する管理ポリシーがあり、SDPのoffer/answer交換後もICE接続が成立しません。署名付きDebianリポジトリから取得したcoturnをローカルのテスト用TCP中継として試しましたが、メディア到達には至りませんでした。ポリシーやTLS・署名検証は無効化していません。coturnはアプリ依存・配布ZIPには含めていません。

従来の最小版では音声・映像を未実装としていましたが、0.2では実装済み・受信検証未完了です。P2P方式は導入が軽い一方、発表者から各受講者への送信が人数分増えます。10〜30人の実授業の配信保証には実機負荷試験と、必要に応じてLiveKit等のSFU統合が必要です。LiveKitの導入・運用・APIキー設定は現時点では行っていません。

パスワードのハッシュ化はNode標準のscrypt、永続化は単一プロセスでのJSONの原子的置換を採用しました。追加の認証ライブラリ・データベース契約は不要ですが、登録アカウント・複数プロセス構成・パスワード復旧は対象外です。
